Antes de nada

Instalar Claude Code en dos minutos

Claude Code es Claude dentro de tu terminal, con permiso para leer y escribir archivos y ejecutar comandos. Si ya lo tienes, salta a los trucos.

01

Instala el programa

curl -fsSL https://claude.ai/install.sh | bash

En Windows, desde PowerShell: irm https://claude.ai/install.ps1 | iex. Si prefieres npm: npm install -g @anthropic-ai/claude-code.

02

Arranca y entra con tu cuenta

claude

La primera vez te abre el navegador para entrar con tu cuenta de Claude (los planes de pago incluyen Claude Code sin coste extra). Y listo: ya puedes escribirle en la terminal como le escribirías en el chat.

El modelo importa

Para el día a día, Opus 5 va sobrado. Cambias de modelo con /model dentro de la sesión.

Configuración

Los seis trucos del creador

El creador de Claude Code contó públicamente cómo lo configura él. Son seis ajustes, y ninguno es cosmético: cada uno quita una fricción concreta. Según tu versión, alguno puede llegar primero al canal beta; si no te aparece, actualiza con claude update.

1 · Modo automático de permisos

Por defecto, Claude Code te pide permiso antes de cada comando. El modo automático mete un clasificador en medio: decide al momento si el comando es seguro y, si lo es, lo ejecuta sin preguntar. Se acabó darle a aceptar cada diez segundos. Cambias de modo de permisos con Mayús+Tab dentro de la sesión.

2 · /fewer-permission-prompts

Escanea tu historial de sesiones, detecta los permisos que apruebas siempre (los mismos comandos, una vez tras otra) y te propone una lista para dejarlos aprobados de una vez en la configuración del proyecto. Lo ejecutas una vez y las sesiones siguientes van solas.

3 · Resúmenes al volver

Si te alejas un rato del ordenador mientras Claude trabaja, al volver te encuentras un resumen: qué ha hecho y qué viene ahora. Sigues por donde ibas sin releer cuarenta líneas de terminal.

4 · Modo foco

Oculta el trabajo intermedio (las búsquedas, los comandos, el ruido) y te enseña solo el resultado. Para sesiones largas donde no quieres supervisar cada paso, es la diferencia entre mirar una terminal y leer un informe.

5 · Niveles de esfuerzo

Con /effort eliges cuánto piensa el modelo antes de actuar. Alto para el día a día; el máximo, para los problemas de verdad duros. Más esfuerzo es más lento y más caro en tokens: se sube cuando el problema lo pide, no por defecto.

6 · Darle una forma de verificarse el importante

Es el truco que más calidad añade y no es un ajuste: es un hábito. Dale siempre a Claude una manera de comprobar su propio trabajo antes de entregártelo: unos tests que pueda ejecutar, una captura de la app funcionando, un comando que valide el resultado. Un agente que se corrige solo vale por dos. Pídelo tal cual: «antes de darlo por terminado, ejecuta los tests y arregla lo que falle».

Skills · concepto

Qué es una skill (de verdad)

Una skill es una carpeta con un archivo de instrucciones dentro. Nada más. El archivo se llama SKILL.md y le enseña a Claude un oficio: cómo quieres que haga una tarea concreta, con tus reglas, tus pasos y tus ejemplos.

La diferencia con un prompt suelto es que la skill vive en disco y se dispara sola: cuando tu petición encaja con la descripción de la skill, Claude la carga y sigue sus instrucciones. También puedes invocarla a mano escribiendo /nombre-de-la-skill.

Dónde viveAlcance
~/.claude/skills/<nombre>/Personal: disponible en todos tus proyectos
.claude/skills/<nombre>/De proyecto: viaja con el repo y la usa todo el equipo

De esto va la locura que viste en el reel: alguien escribe una skill que le enseña a Claude a generar piezas de ingeniería, la sube a GitHub, y cualquiera se la instala. El conocimiento de un experto, empaquetado en una carpeta.

Skills · usar

Instalar una skill hecha

01

Encuentra la skill

El punto de partida es el repositorio oficial de Anthropic, github.com/anthropics/skills, con skills listas para documentos, hojas de cálculo, PDFs y más. A partir de ahí, GitHub: busca «claude skill» y el tema que quieras. La del reel, la que convierte descripciones en piezas de ingeniería exportables a SolidWorks y Fusion, se llama text-to-cad y la encuentras buscándola tal cual en GitHub. Antes de instalar nada, léete el SKILL.md: son instrucciones que Claude va a seguir en tu máquina.

02

Cópiala a tu carpeta de skills

# ejemplo: clonar el repo oficial y copiar una skill concreta
git clone https://github.com/anthropics/skills /tmp/skills
cp -r /tmp/skills/document-skills/pdf ~/.claude/skills/pdf

Eso es todo. No hay registro, no hay tienda, no hay build: una carpeta en su sitio.

03

Compruébala

Abre una sesión nueva de claude y pídele algo que encaje con la skill, o invócala directa con /pdf. Si no se dispara sola, el problema casi siempre es la descripción (lo vemos en los errores, abajo).

Skills · crear

Escribir tu propia skill

Aquí está el truco que casi nadie usa: no hace falta encontrar la skill perfecta, porque te la puedes escribir. O mejor: pedirle a Claude que se la escriba él. Una skill útil sale de una frase como esta:

Crea una skill en ~/.claude/skills/notas-de-parche que convierta la lista
de cambios de mi mod en notas de parche listas para publicar: tono directo,
agrupadas en Nuevo / Cambiado / Arreglado, con los números exactos de cada
ajuste, y una versión corta de tres líneas para Discord.

La anatomía de lo que genera (y que puedes escribir a mano en cinco minutos):

# ~/.claude/skills/notas-de-parche/SKILL.md
---
name: notas-de-parche
description: Convierte una lista de cambios de un mod o un juego en notas
  de parche publicables. Usar cuando pidan notas de parche, changelog o
  resumen de versión.
---

Recibes una lista de cambios en bruto y devuelves dos piezas:

1. Notas de parche completas, agrupadas en Nuevo / Cambiado / Arreglado.
   Cada línea dice el cambio y el número exacto (antes → después).
2. Versión corta: tres líneas para Discord, sin tecnicismos.

Reglas: tono directo, nada de "se ha procedido a", los nombres de los
objetos del juego siempre en cursiva.

Las tres reglas de una skill que funciona

  • La descripción decide si se dispara. Es lo único que Claude lee para elegir skill: escribe en ella las palabras con las que TÚ pides la tarea («notas de parche», «changelog»).
  • Instrucciones, no teoría. El cuerpo son órdenes y ejemplos, como se las darías a alguien nuevo en el equipo. Si tienes un buen y un mal ejemplo, mételos: valen más que diez reglas.
  • Los archivos de apoyo van en la carpeta. Una plantilla, un script, una referencia larga: se guardan junto al SKILL.md y se citan desde él. Así la skill carga ligera y tira de los archivos solo cuando los necesita.

Memoria

CLAUDE.md: la memoria del proyecto

Las skills enseñan oficios; CLAUDE.md enseña tu proyecto. Es un archivo en la raíz del repo que Claude lee al empezar cada sesión: qué es el proyecto, cómo se ejecuta, qué reglas de la casa hay. Se genera un primer borrador con /init y se poda a mano.

# CLAUDE.md — ejemplo mínimo y suficiente
Mod de Stardew Valley con SMAPI. C# en src/, se compila con `dotnet build`.
El resultado se copia solo a la carpeta Mods del juego.

Reglas:
- Los textos visibles en el juego, siempre en español de España.
- Antes de dar nada por hecho: compilar y arrancar el juego una vez.
Corto funciona mejor

CLAUDE.md se carga entero en cada sesión. Veinte líneas que se cumplen valen más que doscientas que diluyen lo importante.

Diagnóstico

Los errores que comete todo el mundo

SíntomaCausa y arreglo
La skill no se dispara solaLa descripción no contiene las palabras con las que pides la tarea. Reescríbela con tus frases reales y prueba en una sesión nueva.
Se dispara la skill equivocadaDos descripciones se pisan. Haz cada una más concreta: «notas de parche de mods de Stardew» en vez de «escribir notas».
Claude ignora partes del SKILL.mdEl archivo es demasiado largo o mezcla teoría con órdenes. Deja las órdenes arriba y mueve la referencia larga a archivos de apoyo.
Cada sesión repite los mismos erroresEso no es una skill: es memoria de proyecto. Va en CLAUDE.md, que se carga siempre.
Aprueba permisos sin pararEjecuta /fewer-permission-prompts y revisa la lista que propone antes de aceptarla.
Skills ajenas, con lupa

Una skill son instrucciones que Claude ejecuta en tu máquina, con tus permisos. Instala solo de fuentes que puedas leer, y léelas. Si un SKILL.md pide descargar y ejecutar cosas raras, ahí se acaba la instalación.
