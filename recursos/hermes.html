Punto de partida

Qué es Hermes y por qué importa

Hermes Agent es un agente de IA de código abierto (licencia MIT) publicado por Nous Research en febrero de 2026. Se instala en tu ordenador, en un servidor de 5 $ al mes o en un móvil Android, y trabaja con el modelo que tú elijas: Claude, GPT, Gemini, los modelos de Nous o uno local. Su frase de presentación lo resume: «el agente que crece contigo».

Lo que lo distingue de los demás no son las herramientas (tiene más de cuarenta: terminal, archivos, búsqueda web, navegador, imágenes, voz, mensajería) sino el bucle de aprendizaje:

  • Crea skills a partir de lo que hace. Cuando resuelve una tarea que se repite, la convierte en una skill (un procedimiento guardado) y la mejora las siguientes veces que la usa.
  • Recuerda entre sesiones. Mantiene notas sobre tu entorno y un perfil sobre ti, y puede buscar en todas las conversaciones pasadas.
  • Vive donde estás tú. Un solo proceso, el gateway, lo conecta a Telegram, Discord, Slack, WhatsApp, Signal, email y Home Assistant, y ejecuta tareas programadas que te llegan a cualquiera de ellos.

Dos cosas que hay que saber antes

Primera: Hermes mejora con el uso, así que la primera semana es peor que la décima; no lo juzgues el primer día. Segunda: es un proyecto joven que publica versiones cada pocas semanas. Si un comando de esta guía no aparece en tu instalación, primero hermes update y luego la documentación oficial en hermes-agent.nousresearch.com/docs.

Si vienes de OpenClaw o de Claude Code

Hermes importa tu configuración: hermes claw migrate trae la de OpenClaw (con --dry-run para ver qué haría antes de tocar nada) y hermes import-agent lee la de Claude Code o Codex.

Decisiones previas

Antes de instalar: requisitos y proveedor

Requisitos

Sistema
Linux, macOS, Windows (nativo por PowerShell, o WSL2, que es la vía más rodada) y Android con Termux. Un VPS Linux barato vale para tenerlo encendido siempre.
Que tengas instalado
Git y curl. En Linux, también xz-utils. Nada más: el instalador trae su propio Python (3.11), Node.js, uv, ripgrep y ffmpeg.
Permisos
Sin sudo. Se instala en tu carpeta de usuario: el código en ~/.hermes/hermes-agent/, el comando en ~/.local/bin/hermes y tus datos en ~/.hermes/.
Modelo
Cualquiera con al menos 64.000 tokens de contexto. Con menos, la compresión de contexto no da abasto y el agente se pierde.

La decisión: quién pone el modelo

Hermes no cobra nada; el modelo sí. Tres caminos, y se pueden cambiar después con un comando.

Nous Portal para empezar

La suscripción de Nous Research: un solo inicio de sesión da acceso a más de 200 modelos (Claude, GPT, Gemini, DeepSeek, los Hermes de Nous) y al Tool Gateway, que pone búsqueda web, generación de imágenes, voz y navegador sin más claves. Hay un nivel gratuito con modelos gratuitos; el plan Plus son 20 $/mes con 22 $ de crédito, y hay Super (100 $) y Ultra (200 $). Se configura con un comando y no hay que gestionar claves.

hermes setup --portal → navegador → elegir modelo → listo

Tus propias claves

Una clave de API de Anthropic, OpenAI, Google u OpenRouter (que reúne cientos de modelos bajo una sola clave). Pagas por uso, por token, y la clave se guarda en ~/.hermes/.env. Es la vía para quien ya tiene claves o quiere control fino del gasto. Las herramientas que necesitan servicios externos (búsqueda web, imágenes) pedirán sus propias claves.

Un modelo local

Ollama, vLLM o llama.cpp en tu máquina o en una GPU alquilada. Gratis por token, privado, y exigente: necesitas un modelo con 64k de contexto que corra decentemente. En hermes model eliges «Custom endpoint» y pones la dirección (con Ollama, http://localhost:11434/v1). Para montar la GPU por horas, la guía de Vast.ai.

Fase 1

Instalar

01

Linux, macOS, WSL2 y Android (Termux)

curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash

El instalador descarga el código, crea un entorno de Python aislado con uv, instala Node.js si no tienes una versión reciente, y deja el comando hermes en ~/.local/bin. Tarda unos minutos. No lo ejecutes con sudo: no lo necesita y te dejaría los archivos con el dueño equivocado.

02

Windows

# PowerShell, instalación nativa
iex (irm https://hermes-agent.nousresearch.com/install.ps1)

La instalación nativa en Windows es reciente. Si algo se resiste, la vía rodada es WSL2 (Ubuntu dentro de Windows) con el comando del paso 1. Para Mac y Windows existe además un instalador de escritorio con interfaz gráfica en la web oficial; instala lo mismo, con ventana.

03

Recarga la terminal y comprueba

source ~/.bashrc      # en Mac con zsh: source ~/.zshrc
hermes --version
hermes doctor

hermes doctor revisa el entorno, detecta lo que falta y te dice cómo arreglarlo. Es el primer comando que hay que lanzar cada vez que algo raro pase.

Bien

hermes --version imprime un número de versión y hermes doctor no muestra errores en rojo. Si dice que falta un proveedor de modelo, es normal: eso es el siguiente paso.

04

Si algo falla en la instalación

MensajeArreglo
hermes: command not foundLa terminal no ha recargado el PATH. source ~/.bashrc (o ~/.zshrc), o cierra y abre la terminal.
Python demasiado antiguoHermes necesita 3.11 o superior. En Ubuntu, sudo apt install python3.12; en Mac, brew install python@3.12. Luego repite el instalador.
uv: command not foundInstálalo: curl -LsSf https://astral.sh/uv/install.sh | sh y repite.
Permission deniedHas usado sudo o la carpeta de usuario no es tuya. Sin sudo, y comprueba que puedes escribir en ~/.local/bin.

Fase 2

Configurar

05

El asistente: hermes setup

hermes setup            # asistente completo
hermes setup --portal   # directo a Nous Portal, en un solo paso

El asistente ofrece tres modos: Quick Setup (Nous Portal, el recomendado si empiezas), Full Setup (eliges proveedor y claves a mano) y Blank Slate (lo mínimo, activando cada cosa tú). Con --portal se abre el navegador, inicias sesión, eliges modelo del catálogo y el Tool Gateway queda activado; las credenciales se guardan en ~/.hermes/auth.json.

06

Elegir o cambiar de modelo: hermes model

hermes model                              # menú interactivo de proveedor y modelo
hermes config set model proveedor/modelo   # o directamente, sabiendo el nombre

Si eliges un proveedor con clave (Anthropic, OpenAI, OpenRouter), te la pide y la guarda en ~/.hermes/.env. Para un modelo local, «Custom endpoint» y la dirección de tu servidor. Los proveedores que configures se quedan disponibles: cambiar de uno a otro después es volver a hermes model, o /model en mitad de una conversación.

07

Activar herramientas: hermes tools

hermes tools

Un menú para encender y apagar conjuntos de herramientas: terminal, file, web (búsqueda y extracción), browser, vision, image_gen, voz, memoria, tareas programadas y más. Con Nous Portal, la búsqueda web, las imágenes, la voz y el navegador funcionan sin claves adicionales; con tus propias claves, cada una te pedirá la suya. La búsqueda en X (Twitter) viene apagada y requiere credenciales de xAI.

08

Dónde vive todo: la carpeta ~/.hermes

config.yaml
Toda la configuración que no es secreta: modelo, terminal, compresión, herramientas, aprobaciones.
.env
Claves de API y tokens de bots. Sólo secretos, y con permisos 600.
auth.json
Credenciales de inicio de sesión (Nous Portal).
SOUL.md
La identidad del agente: quién es, cómo habla, qué prioriza. Lo editas tú.
memories/
MEMORY.md y USER.md, la memoria persistente (sección 7).
skills/
Las skills instaladas y las que crea el agente (sección 6).
sessions/, state.db, logs/
Conversaciones, la base de datos con búsqueda de sesiones y los registros.
hermes config            # ver la configuración
hermes config edit       # abrirla en el editor
hermes config get clave   # leer un valor
hermes config set clave valor
hermes config check      # comprobar que no falta nada

Un config.yaml mínimo y sensato para empezar en tu ordenador:

# ~/.hermes/config.yaml
model: proveedor/modelo
provider: nous            # o anthropic, openrouter, openai…

terminal:
  backend: local          # en un servidor, docker (sección 10)
  timeout: 180

approvals:
  mode: smart             # smart | manual | off

compression:
  enabled: true

memory:
  memory_enabled: true
  user_profile_enabled: true

Orden de prioridad si algo se define en dos sitios: lo que pasas en la línea de comandos manda sobre config.yaml, que manda sobre .env, que manda sobre los valores por defecto.

Fase 3

Primer uso: chat, comandos y sesiones

09

Arranca y pide algo pequeño

cd carpeta-de-un-proyecto
hermes            # interfaz clásica
hermes --tui      # interfaz moderna, con paneles
Mira la carpeta en la que estamos y dime, en cinco líneas, qué es este
proyecto y cuál parece el archivo principal. No modifiques nada.

Verás el bucle: lista archivos, lee alguno, resume. Para escribir varias líneas, Alt+Intro (también Ctrl+J o Mayús+Intro). Para interrumpirlo, escribe el mensaje nuevo y pulsa Intro; también vale Ctrl+C.

11

Sesiones: retomar, buscar, lanzar en una línea

hermes -c                          # retomar la última sesión
hermes --resume id-o-título        # retomar una concreta
hermes sessions list               # ver las anteriores
hermes journey                     # línea de tiempo de skills y memorias aprendidas

hermes chat -q "Resume este repositorio en 5 puntos"   # sesión con pregunta inicial
hermes -z "¿Qué hora es en Tokio?"                     # una respuesta y fuera; para scripts
hermes chat --image foto.png -q "¿Qué pone aquí?"      # con una imagen

Cada sesión es una conversación con su contexto. La regla de siempre: una sesión por tarea. Lo importante que quieras que sobreviva va a la memoria, no al chat.

12

Cuando pide permiso

Antes de ejecutar un comando que pueda hacer daño (borrar, sobrescribir, descargar y ejecutar), Hermes se para y pregunta. En el modo smart, un modelo auxiliar decide qué es inocuo (se ejecuta), qué es claramente peligroso (se niega) y qué es dudoso (te pregunta). Respondes con una de cuatro opciones:

  • once · sólo esta vez.
  • session · durante esta sesión.
  • always · siempre: añade el patrón a command_allowlist en la configuración.
  • deny · no (es la opción por defecto si no contestas).

Empieza respondiendo once y pasa a always sólo con comandos que veas repetirse y entiendas. Hay comandos que Hermes no ejecuta nunca, ni aunque se lo pidas (sección 10).

Personalidad y perfiles

SOUL.md define quién es tu agente; /personality cambia el tono al vuelo. Y si quieres un Hermes para el trabajo y otro para lo personal, con memorias y skills separadas: hermes profile create trabajo y luego hermes -p trabajo.

Lo que lo hace distinto

Skills: usar, instalar y dejar que las cree

Una skill es una carpeta en ~/.hermes/skills/ con un archivo SKILL.md que describe un procedimiento: cuándo usarlo, los pasos, las trampas y cómo comprobar el resultado. Puede llevar al lado plantillas, scripts y referencias. El formato sigue el estándar abierto de agentskills.io, así que las skills de Claude Code, OpenAI o la comunidad funcionan aquí.

# ~/.hermes/skills/contenido/informe-semanal/SKILL.md
---
name: informe-semanal
description: Informe semanal de métricas de contenido en Notion
version: 1.0.0
metadata:
  hermes:
    tags: [contenido, notion]
    requires_toolsets: [terminal, web]
---

## When to Use
Cuando pidan el informe semanal, el resumen de la semana o las métricas.

## Procedure
1. Leer las publicaciones de los últimos 7 días de la base de Notion.
2. Calcular alcance, retención media y guardados por pieza.
3. Escribir el informe con la plantilla de templates/informe.md.

## Verification
Las cifras del informe coinciden con las de Notion. Si una falta, se
marca como [SIN DATO], no se estima.

Usar una skill

Se cargan solas cuando tu petición encaja con su descripción, o a mano: /informe-semanal hazme el de esta semana. Puedes encadenar hasta cinco en un mensaje (/skill-uno /skill-dos arregla esto). Y con /skills ves las que hay cargadas.

Instalar del hub

hermes skills browse                          # ver el catálogo
hermes skills search notion                   # buscar en todas las fuentes
hermes skills inspect fuente/ruta/skill       # leerla antes de instalar
hermes skills install fuente/ruta/skill
hermes skills install https://ejemplo.com/SKILL.md --name mi-skill
hermes skills list                            # instaladas
hermes skills check                           # ¿hay cambios arriba?
hermes skills update
hermes skills uninstall nombre

Las fuentes tienen niveles de confianza: official/ (las que empaqueta el propio Hermes) y los repositorios de openai/, anthropics/, huggingface/ y NVIDIA/ son de confianza; skills-sh/ (el directorio público de Vercel) y las URLs sueltas son «comunidad». Todas pasan por un escáner que busca exfiltración de datos, inyección de prompt y comandos destructivos: lo dudoso se puede forzar con --force después de leerlo; lo peligroso se bloquea siempre.

Dejar que las cree él

Es la parte que no tiene nadie más. Cuando Hermes resuelve algo que huele a repetible, guarda el procedimiento como skill con su herramienta interna skill_manage, y la va afinando cada vez que la usa. Puedes provocarlo:

Lo que acabamos de hacer lo voy a necesitar cada semana. Conviértelo
en una skill llamada informe-semanal, con los pasos exactos que has
seguido y la comprobación final de que las cifras coinciden.

Si prefieres revisar antes de que escriba nada en disco, activa la aprobación de escritura y revisa lo que propone:

# en config.yaml
skills:
  write_approval: true

# en el chat
/skills pending          # qué quiere escribir
/skills diff id          # ver el cambio
/skills approve id       # o /skills reject id
Skills de otros proyectos

Si tienes skills en otras carpetas (las de Claude Code, las de tu equipo), no hace falta copiarlas: en config.yaml, skills.external_dirs con la lista de rutas. Las skills que vienen dentro de un repositorio clonado exigen confianza explícita con hermes skills trust antes de cargarse.

Lo que recuerda

Memoria: lo que recuerda de ti

Dos archivos de texto en ~/.hermes/memories/, que el agente mantiene y tú puedes editar:

MEMORY.md
Sus notas: cómo es tu entorno, convenciones, cosas que ha aprendido. Límite de 2.200 caracteres (unos 800 tokens).
USER.md
Tu perfil: preferencias, forma de comunicarte, qué esperas de él. Límite de 1.375 caracteres (unos 500 tokens).

Los límites son a propósito: la memoria se carga entera en el arranque de cada sesión, y una memoria corta que se cumple vale más que una larga que diluye. Cuando se llena, la herramienta devuelve un error y el agente tiene que consolidar antes de añadir; no se trunca nada en silencio. Lo que se guarda durante una sesión queda en disco al momento pero se ve en la siguiente: el arranque es una foto fija.

Además de esos dos archivos, Hermes puede buscar en todas las conversaciones anteriores (búsqueda de texto completo sobre ~/.hermes/state.db), así que encuentra cosas que no están en la memoria activa sin gastar contexto en cargarlas.

Recuerda que mis vídeos van siempre en español de España, que mi
audiencia no es técnica y que odio las frases de relleno.

¿Qué sabes de mí? Enséñame tu USER.md.

Busca en nuestras conversaciones anteriores cuándo hablamos del
formato de los guiones y resume lo que decidimos.
# config.yaml · interruptores de la memoria
memory:
  memory_enabled: true
  user_profile_enabled: true
  write_approval: false     # true: revisar con /memory pending y /memory approve

Para ver cómo ha ido creciendo (qué skills y qué memorias ha ido aprendiendo y cuándo): hermes journey. Y si quieres memoria semántica o grafos de conocimiento, hermes memory conecta proveedores externos como Honcho, Mem0 o Supermemory. Para empezar, los dos archivos sobran.

Fase 4

Al móvil: Telegram, Discord y WhatsApp

El gateway es un único proceso que conecta Hermes a todas las plataformas a la vez y ejecuta las tareas programadas. Lo configuras una vez por plataforma y lo dejas encendido. Telegram es el más sencillo y el más estable: empieza por ahí.

13

Cómo se arranca y se mantiene encendido

hermes gateway setup          # asistente: elegir plataforma, pegar tokens
hermes gateway                # arrancar en primer plano (para probar)
hermes gateway install        # instalarlo como servicio de usuario
sudo hermes gateway install --system   # Linux: que arranque con la máquina
hermes gateway status
hermes gateway stop

En WSL2 los servicios del sistema no siempre funcionan: usa tmux o nohup hermes gateway run para dejarlo en segundo plano.

14

Telegram

  1. En Telegram, abre @BotFather, escribe /newbot, dale un nombre y un usuario que termine en bot. Te devuelve el token (algo como 123456789:ABCdef…). Es una contraseña: no lo pegues en ningún chat.
  2. Averigua tu ID numérico de usuario escribiendo a @userinfobot. No es tu nombre de usuario: es un número.
  3. Configura: hermes gateway setup, elige Telegram, pega el token y tu ID. O a mano, en ~/.hermes/.env:
TELEGRAM_BOT_TOKEN=123456789:ABCdefGHIjklMNOpqrSTUvwxYZ
TELEGRAM_ALLOWED_USERS=123456789      # varios: separados por comas

Arranca con hermes gateway y escríbele al bot. Debería contestar en segundos. Dentro del chat tienes /new, /model, /status, /skill, /help y /stop para parar una tarea.

En grupos

Por defecto los bots de Telegram sólo ven los comandos en los grupos. Para que lea todos los mensajes: en @BotFather, /mybots → tu bot → Bot Settings → Group Privacy → Turn off, y saca y vuelve a meter al bot en el grupo. Autoriza el grupo con TELEGRAM_GROUP_ALLOWED_CHATS (los IDs de grupo son negativos) y, si quieres que sólo responda cuando le mencionan, telegram: { require_mention: true } en config.yaml.

15

El canal «casa»: dónde llegan las tareas programadas

Las tareas programadas necesitan saber a qué chat mandar el resultado. Desde el propio chat, /sethome lo fija; o en .env:

TELEGRAM_HOME_CHANNEL=123456789            # tu ID si es un chat privado; negativo si es un grupo
TELEGRAM_HOME_CHANNEL_NAME="Mis avisos"
16

Discord

  1. En discord.com/developers/applications, New Application. En la pestaña Bot, activa los Privileged Gateway Intents Server Members y Message Content (sin el segundo, el bot no lee los mensajes). Reset Token y copia el token: sólo se muestra una vez.
  2. En Installation, enlace de invitación con los ámbitos bot y applications.commands y los permisos de ver canales, enviar mensajes, insertar enlaces, adjuntar archivos y leer el historial. Abre el enlace e invita al bot a tu servidor.
  3. Tu ID de usuario: en Discord, Ajustes → Avanzado → Modo desarrollador, y luego clic derecho sobre tu nombre → Copiar ID.
DISCORD_BOT_TOKEN=tu-token
DISCORD_ALLOWED_USERS=tu-id-numerico
DISCORD_REQUIRE_MENTION=true          # en canales, sólo responde si le mencionas

hermes gateway y el bot aparece en línea. Para canales donde quieras que responda sin mención, DISCORD_FREE_RESPONSE_CHANNELS con sus IDs.

17

WhatsApp

hermes whatsapp

El asistente te pregunta el modo (bot, con un número dedicado; o self-chat, hablando contigo mismo en tu propio número) y muestra un código QR. En el móvil: WhatsApp → Ajustes → Dispositivos vinculados → Vincular un dispositivo, y escanea. Necesita Node.js (18 o superior), que el instalador ya dejó puesto.

WHATSAPP_ENABLED=true
WHATSAPP_MODE=bot                     # bot | self-chat
WHATSAPP_ALLOWED_USERS=34600000000     # con prefijo de país, sin el +
Riesgo de bloqueo

WhatsApp no admite oficialmente bots fuera de su API de empresa; un número vinculado así puede acabar bloqueado. Si el número te importa, usa uno secundario, o la vía oficial con la API de WhatsApp Business (hermes whatsapp-cloud). Cada perfil de Hermes admite un solo número, y la carpeta ~/.hermes/platforms/whatsapp/session es tu sesión de WhatsApp: protégela como una contraseña.

18

Quién puede hablar con tu agente

Por defecto, nadie: si no hay listas de permitidos, el gateway rechaza a todo el mundo y te avisa al arrancar. Dos formas de abrir la puerta:

  • Listas por plataforma, como las de arriba (TELEGRAM_ALLOWED_USERS, DISCORD_ALLOWED_USERS…) o una global, GATEWAY_ALLOWED_USERS.
  • Emparejamiento: un desconocido que escribe recibe un código de ocho caracteres (caduca en una hora) y tú lo apruebas desde la terminal.
hermes pairing approve telegram CÓDIGO
hermes pairing list
hermes pairing revoke telegram id-de-usuario
Nunca

GATEWAY_ALLOW_ALL_USERS=true en un agente con terminal es dar tu ordenador a cualquiera que encuentre el bot. No existe un caso en que compense.

Slack, Signal, email y Home Assistant se configuran con el mismo hermes gateway setup; para Slack, hermes slack genera el manifiesto de la app con sus comandos.

Que trabaje solo

Tareas programadas

Con el gateway encendido, Hermes ejecuta tareas a la hora que le digas, en una sesión nueva cada vez, y te manda el resultado a donde quieras. Se pide en lenguaje normal:

Cada día laborable a las 8:00, revisa las novedades de los tres canales
de YouTube de mi lista canales.txt, resume en cinco líneas lo que han
publicado y mándamelo por Telegram. Si no hay nada nuevo, no me escribas.

O desde la terminal y el chat, con control fino:

hermes cron create "every 2h" "Comprueba que la web de la academia responde"
hermes cron list
hermes cron run id            # ejecutarla ahora
hermes cron pause id          # y resume
hermes cron edit id --schedule "weekdays at 9am"
hermes cron remove id

# en el chat: /cron add "every 1h" "Resume las novedades" --skill vigilar-blog

Una vez, dentro de"in 30m", "in 2h", "in 1d"

Lenguaje natural"every monday 9am", "daily at 7am", "weekdays at 9am"
Expresión cron"0 9 * * *" (a diario a las 9), "0 9 * * 1-5" (laborables)
Fecha exacta"2026-10-01T09:00:00"

El resultado va a origin (donde se creó la tarea), a local (se guarda en ~/.hermes/cron/output/), a una plataforma concreta (telegram, discord, slack, email…) o a all. El gateway comprueba el reloj cada minuto.

Nadie aprueba de madrugada

Una tarea programada que tropiece con un comando que requiere aprobación se queda sin respuesta. Por defecto, en ese caso Hermes deniega (approvals.cron_mode: deny). Diseña las tareas nocturnas para que no necesiten comandos delicados, o añade a la lista de permitidos exactamente los que necesiten. Un ejemplo completo de pipeline nocturno, con aprobación desde el móvil de lo irreversible, está en la guía de modernizar webs.

Sin puertas abiertas

Seguridad: aprobaciones, contenedores y VPS

Aprobaciones

# config.yaml
approvals:
  mode: smart              # smart (recomendado) | manual (pregunta siempre) | off
  timeout: 300             # segundos esperando tu respuesta
  cron_mode: deny          # qué hacer sin nadie delante
  deny:                    # tus propias prohibiciones, siempre
    - "git push --force*"
    - "*curl*|*sh*"

Hay una lista negra que no se puede saltar, ni con --yolo ni con mode: off: borrar la raíz del disco, bombas de procesos, formatear discos montados, descargar-y-ejecutar de una tubería. Y hay archivos que el agente no puede escribir aunque quiera: ~/.ssh, ~/.aws, sus propios auth.json y .env, y los .env de tus proyectos. La variable HERMES_WRITE_SAFE_ROOT restringe además todas las escrituras a las carpetas que digas.

Si lo montas en un VPS

  • Listas de permitidos explícitas o emparejamiento. Jamás «permitir a todos».
  • Backend docker con límites de CPU, memoria y disco, y usuario sin privilegios.
  • Secretos en ~/.hermes/.env con permisos 600, y nada más ahí.
  • Revisar de vez en cuando command_allowlist en la configuración y los registros en ~/.hermes/logs/.
  • Actualizar con hermes update; hermes doctor avisa además de paquetes de Python comprometidos.
  • Si quieres cinturón y tirantes: gateway en una máquina y ejecución en otra por ssh, y security.allow_lazy_installs: false para que ninguna configuración pueda instalar dependencias por su cuenta.
Lo que ya viene puesto

Hermes escanea los archivos de contexto (AGENTS.md, SOUL.md, .cursorrules) en busca de instrucciones inyectadas, bloquea peticiones a direcciones internas y de metadatos de la nube, y filtra las variables de entorno que llegan a los servidores MCP. No sustituye a las reglas de arriba, pero es más de lo que trae la mayoría.

hermes update                  # última versión; sincroniza las skills de todos los perfiles

hermes dashboard               # panel web de configuración y sesiones

Los perfiles exportados no llevan credenciales; para una copia completa, hermes backup. Y si algún día te pasas al ordenador nuevo: backup en el viejo, instalador en el nuevo, import. Diez minutos.

Diagnóstico

Cuando algo no va

Antes de nada, la secuencia oficial de recuperación: hermes doctor → hermes model → hermes setup → hermes sessions list → hermes -c → hermes gateway status. Casi todo se arregla en los dos primeros.

SíntomaCausa y arreglo
Respuestas vacías o cortadasProveedor mal configurado o clave caducada. hermes model, comprueba la autenticación y vuelve a elegir el modelo.
Un modelo local da timeout con contextos grandesEn .env: HERMES_STREAM_READ_TIMEOUT=1800. Y prueba el endpoint por separado antes de culpar a Hermes.
«Session not found»hermes sessions list y confirma que estás en el perfil correcto (-p).
El bot no contesta a nadieNo hay lista de permitidos: el gateway deniega por defecto y lo avisa al arrancar. Añade tu ID o usa el emparejamiento.
El bot responde en privado pero no en el grupoPrivacidad de grupo activada en BotFather. Desactívala, saca al bot del grupo y vuelve a meterlo.
Las tareas programadas no se ejecutanEl gateway no está encendido. hermes gateway status; instálalo como servicio.
Una tarea nocturna «no hizo nada»Tropezó con una aprobación y, sin nadie delante, denegó. Mira hermes logs y rediseña la tarea o añade el comando a la lista de permitidos.
WhatsApp se desconectaVuelve a escanear el QR con hermes whatsapp. Si se repite, es el riesgo de la vía no oficial: valora hermes whatsapp-cloud.
Un comando de esta guía no existehermes update. El proyecto cambia deprisa; hermes --help y /help dicen lo que hay en tu versión.
Necesitas ayuda de la comunidadhermes dump genera un resumen de tu instalación sin secretos, listo para pegar; hermes debug share sube un informe con los registros.
